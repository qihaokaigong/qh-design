# 折叠列表组合规范

2026-11-16。适用于有摘要、汇总值、重复明细和行操作的分组列表，例如同一事项的多段时间记录。本文规定组合与交互；不新增核心组件 API、Token 或 Registry 安装项。

## 开源参考与采用方式

| 参考                                                                                       | 采用的规则                                        | QH 中的落点                                              |
| ------------------------------------------------------------------------------------------ | ------------------------------------------------- | -------------------------------------------------------- |
| [shadcn/ui Item](https://ui.shadcn.com/docs/components/base/item)                          | 内容、描述和操作独立组织                          | 摘要行划分为标题与元信息、汇总值、操作区                 |
| [shadcn/ui Collapsible](https://ui.shadcn.com/docs/components/base/collapsible)            | 通过独立触发器控制关联明细                        | 业务操作与展开触发器为兄弟元素                           |
| [GitHub Primer 渐进披露](https://primer.style/product/ui-patterns/progressive-disclosure/) | 披露内容时保持上下文，图标配合明确文字            | 展开后保留摘要、汇总和主要操作，箭头与标题、状态提示组合 |
| [Base UI Collapsible](https://base-ui.com/react/components/collapsible)                    | Root、Trigger、Panel 分离，提供开放状态和高度变量 | 已使用 Base UI 的应用可复用安装的原语承载业务组合        |

## 选择组件与边界

- FAQ、设置等只有标题和内容的独立区块，优先使用 QH `Accordion`，保留其标题层级和方向键模型。
- 摘要上有独立业务操作的分组列表，采用单个披露触发器与操作区的组合。不要将操作按钮放入 Trigger，也不要强行让普通 Button 的内部居中标签承担全行布局。
- 复用项目已安装且经过验证的披露原语。若 QH 现有 API 不能表达独立摘要操作，允许应用层组合；不为一个场景扩大核心 API，不要求应用新增另一套原语依赖。
- Button、IconButton、Menu 使用 QH 核心组件。分组、排序、汇总、序号、权限、数据读取和 mutation 保留在应用层。

## 摘要与明细层级

- 摘要从左到右为：披露箭头、左对齐的标题与元信息、右对齐的汇总值、独立操作区。标题自然换行，不因长文本隐藏箭头、段数或操作。
- 多段分组默认收起，保留标题、段数、汇总值和主要操作；单条记录直接展示，不出现无意义的展开箭头。若任务需要立即检查明细，可显式选择默认展开。
- 触发器包含标题与展开提示，例如“展开明细 / 收起明细”；点击摘要内容切换明细，不执行业务 mutation。
- 展开后摘要保持原位，汇总值与主要操作不消失、不换列。分组和单条记录共享汇总列与操作列；需要时预留没有菜单的空槽位，空槽不参与键盘导航。
- 明细使用一层浅色背景、缩进及细分隔线表达从属关系；需要更明确的顺序时增加细连接线、节点和业务序号。使用 `--qh-color-surface-subtle`、`--qh-color-border`、`--qh-color-text-muted`，不增加原始颜色或卡片嵌套。
- 明细不重复组标题，显示能区分每条记录的信息，例如“第 2 段”、起止时间和本段时长。序号、时间、文字共同表达关系，不只依赖颜色或连接线。
- 行内完整时长与按日期裁剪的统计必须保持不同口径；跨天信息、待同步、冲突和错误说明不得因折叠样式而丢失。

## 操作与响应式布局

- 高频动作在摘要与单条记录上使用带文字的 outline Button，并在收起、展开时保持可见。低频编辑、删除放入始终可发现的 ghost IconButton + Menu，不依赖 hover。
- 图标按钮名称标识对象；重复明细额外包含段号等区分信息。菜单使用完整动作文字，危险操作使用 destructive 语义；执行仍遵守业务已有的确认和权限规则。
- 展开不改变操作可用性；请求中、无权限或已有互斥任务时，沿用业务禁用规则。展开状态本身不应禁用整行或阻止阅读。
- 从 320px 开始设计。窄屏先保证标题阅读空间，再将操作换到下行；汇总值和菜单保留可读宽度。长标题、跨天区间和小时级时长都可换行，禁止用页面横向滚动或截断关键内容解决挤压。
- 默认触控目标至少 44 × 44px，使用 4px 间距尺度、8px 控件圆角、12px 列表外框圆角。只保留一层列表边界，操作之间的装饰分隔不得替代控件自身边界。
- 不通过 className 覆盖 QH Button 的内部排版或视觉状态。让应用拥有的布局容器负责列、间距和换行。

## 语义、键盘与动画

- 列表使用 `ol/ul` 与 `li` 表达层级；Trigger 使用真实按钮，保持稳定的 `aria-controls` 关联及准确的 `aria-expanded`。收起后的明细不能进入 Tab 顺序。
- Enter 和 Space 切换；Tab 按原生顺序经过披露、主要操作和菜单。只有使用 Accordion 时才采用其方向键导航，不给普通分组列表添加 tree 或 toolbar 角色。
- 菜单保留原语提供的方向键、Escape、外部点击和焦点恢复。选择编辑后聚焦编辑表单，取消或完成后将焦点交回该条记录仍存在的菜单按钮。
- 展开使用短暂高度过渡并同步旋转箭头，建议 180ms；不循环、不延迟业务操作。`prefers-reduced-motion: reduce` 下取消高度与箭头过渡，立即完成切换。

## 验收

- 桌面、320px 窄屏和 200% 文字放大下，长标题、跨天区间、小时级时长不溢出；摘要与单条记录列对齐。
- 收起与展开后汇总值、主要操作一致；展开只披露正确的明细，不发送 mutation。
- Enter、Space、Tab、菜单方向键与 Escape 可用；隐藏明细不可聚焦；编辑与取消的焦点正确。
- 每段编辑、删除命中正确业务 ID；禁用与保存中不能重复执行；既有同步和冲突提示可见。
- 减少动画偏好下内容仍能展开收起，焦点轮廓和触控目标保持完整。
